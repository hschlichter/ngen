Streaming Domain Review

What is loaded now follows the world's own authored residency: each cell's streaming heuristic gives load and unload radii, the engine keeps the level they ask for and every coarser level, and nothing loads or unloads because time passed. The 10 s unload delay is gone. Drawing falls back only to coarser levels; when authoring leaves a gap, the engine shows it (a late draw, an authoring finding) instead of covering it. This review follows the change from the packer to a drawn level and into the records.

The change is contained to how a streaming root decides its resident levels and its drawn level; composition, placement and the renderer are unchanged in shape. Imaging selection gives the same levels as before at the village. The packer and both check tools read the new attribute the same way as OpenUSD (6,700 heuristic lines identical). Open questions: the evaluation cost (it quadrupled, still small), the lead metric (it doesn't measure what the world's replay measures), and memory, which the chain of coarser levels raises with no budget yet to bound it.

The flow

From an authored radius to a drawn level and a record

The packer keeps the custom attribute; the World reads the domain; the scene thread computes the state, gives the composer the resident set, and the placement pass picks the drawn level; a measurement pass reads the result. On the main thread, fly moves the camera that drives it all. Teal boxes are new behaviour; white ones changed shape only. Numbers match the walkthrough.

The packer keeps the unload radii

src/asset/pack/usd/usdpacker.cpp · src/asset/README.md

The layer pack keeps only attributes the engine reads. streaming:unloadThresholds is a custom attribute of the world's own, so it was dropped; now every streaming: attribute is kept. The packer binary is part of each pack's cache key, so the world repacks on its next request (one cold run had a 1.5 s frame while loading; warm, 64 ms).

3

Residency: the state, the chain, no clock

scene thread, ViewScene::evaluateLevels
src/view/viewscene.cpp · viewscene.h

Before: a root loaded the level imaging picked plus its coarsest; a level no longer picked stayed 10 s on a timer (keepLevel, releaseLevels, a timed wake of the scene thread). Now, per placed root, the imaging pick is unchanged (selected, the level drawn), and the streaming heuristic gives a state from the camera's distance and the previous state. Resident is the state's level and every coarser one. A root without a streaming heuristic keeps the selected level and every coarser one. A hand-set level is the one exception, as the tool asks for it.

A root's children are placed, and so evaluated, only while its finest level is resident. Since a region's full is resident exactly when its state is 0, its tiles are visited only then, which is the spec's "children only while full is wanted".

Check here
  • The state persists while a root stays placed, and is forgotten once it isn't: a tile whose region drops below full starts from its load radii when it comes back.
  • Each evaluation now tunes every heuristic of every root and runs the authoring check per root (with the parent found by walking the path up). That is the 0.25 → 0.97 ms rise at the village; the flight averaged 2.2 ms for its last evaluation over 164 roots. Findings change only with tuning, so they could be cached.
  • heuristicLevels (the imaging hysteresis) is still never forgotten; only the streaming state is cleaned up. Unchanged from before.

Drawing never goes finer than selected

scene thread, placement pass
src/view/placement.cpp

drawnLevelOf still draws the finest ready level at or coarser than the selected one, and while none is ready, the coarsest loaded one as it arrives. The change is its last case: if the coarsest loaded level is finer than the selected one, it now returns nothing (a hole, counted) instead of drawing it. With the chain resident this can't happen; the case exists so the engine doesn't hide it if it ever does.

Risks

What to weigh

cost

Memory has no bound yet

Keeping every coarser level raises the resident set; the spec measures about 1.5× its draw-only policy. With no budget, a world with tighter radii or denser levels grows until something runs out. Stage 3.

Budgets are their own plan (plan_streaming_budgets.md); the order matters.

cost

Evaluation is four times as expensive

0.25 → 0.97 ms per evaluation at 196 roots, on the scene thread, each time the camera moves (21,847 evaluations over the flight). Most is re-tuning heuristics and re-checking the contract, which only change with tuning. Stage 3.

Cache findings and tuned heuristics per tuning revision now, or wait until it shows.

behaviour

The lead doesn't mean what the replay's means

Measured in both directions, so its median reflects coarser levels held long before they are selected. Late switches and root-seconds coarser are comparable; the lead isn't yet. Stage 6.

Split finer and coarser leads before tuning radii by it.

maintenance

Two loading rules in the composer

The view's set, or the old default (wanted plus coarsest) for readers that give none, kept so the two check tools agree. Stage 4.

Accept, or move the check tools to the chain rule too.

scope

The contract check reaches only what is composed

A tile is checked only while its region's full level is composed: in the view while it is placed, in ngen-worldcheck when passed with --lod. Stage 2.

Fine for now; a whole-world check would compose every region's full level.
