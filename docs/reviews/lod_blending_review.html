LOD Blending Review

Render-LOD levels now cross-fade inside the blend bands an asset authors, and each LOD root is measured by distance or screen size by a view-wide preference, distance first. This review follows the change through the engine stage by stage, with the code that does each step and what to check in it.

Summary
Agrees with OpenUSD71 of 71 camerasThe engine picks the same LOD level, and the same point in a fade, as OpenUSD's own LOD code. Checked by distance and by screen size; the largest gap was a millionth of a level.
No holes in a fadeEvery pixelHalfway through a fade, each of the image's 3.7 million pixels shows one of the two levels, exactly as the dither pattern says.
Cost of one fading tree+0.12 ms a frameBoth levels draw while it fades (4 draw calls instead of 2). G-buffer pass 0.08 → 0.15 ms, shadow pass 0.04 → 0.09 ms; a 60 fps frame has 16.7 ms.
Everything elseUnchangedDraws that aren't fading take the same path as before; the eight reference screenshots come out identical to the byte.

Four things change: the World keeps every LOD heuristic a root names; the view chooses one per root by a preference; the GPU computes UsdLod's fractional level and, inside a band, a second level and its share; and the cutout pipelines dither the two levels against each other. Nothing new runs for a draw that isn't fading.

The flow

From the authored heuristic to a dithered pixel

The scene thread turns what USD authors into a record per placed group. The render thread uploads changed records; each frame the GPU picks levels, culls, and draws. Numbers match the walkthrough below.

Tinted boxes are new behaviour. Untinted ones changed shape only (more fields, a bigger record) or are unchanged plumbing the change rides on.

1 · World

4 · GPU pick

Measure, pick, then a fade level only when it can be drawn

shaders/lodselect.comp · src/world/world.cpp (the CPU twin)

One thread per group. The measure follows the group's kind; the pick is the same rule as pickLodLevel on the CPU. A band at a boundary makes the switch a pure function of the measure (no hysteresis there); without one, going coarser still waits for the 20% margin against last frame's wanted level.

shaders/lodselect.comp · distanceOf, as UsdLodDistanceHeuristicQuery::ComputeDistancefloat distanceOf(Group group) {
    vec3 target = group.point;
    if (group.hasBox != 0u) {
        vec3 eyeRoot = transformPoint(group.toRoot, push.eye);
        if (all(greaterThanEqual(eyeRoot, group.boxMin)) && all(lessThanEqual(eyeRoot, group.boxMax))) {
            return 0.0;                             // inside the box
        }
        target = clamp(eyeRoot, group.boxMin, group.boxMax);
    }
    return length(transformPoint(group.toWorld, target) - push.eye);
}
src/world/world.cpp · pickLodLevel (the rule; lodselect.comp's pickLevel is the same, line for line)auto past = [&](float edge) { return distance ? measure >= edge : measure <= edge; };
// A boundary's band: its blend threshold, clamped to the next threshold as UsdLod does.
auto band = [&](uint32_t k) -> std::optional<float> { … };
float coarserScale = distance ? 1.0f / std::sqrt(1.0f - hysteresis) : 1.0f - hysteresis;
// Finer: every boundary fully past. Coarser: the same, a boundary without a band only past the margin.
while (finer < boundaries && past(band(finer).value_or(thresholds[finer]))) { finer++; }
while (coarser < boundaries && past(band(coarser).value_or(thresholds[coarser] * coarserScale))) { coarser++; }
uint32_t level = previous;
if (finer < previous) { level = finer; } else if (coarser > previous) { level = coarser; }
// Inside the band past this level's threshold: the next level's share, UsdLod's fractional index.
if (auto edge = band(level); edge && past(thresholds[level]) && !past(*edge)) {
    pick.blend = clamp((measure - thresholds[level]) / (*edge - thresholds[level]), 0, 1);
}

Check here
  • The distance hysteresis is 1 / sqrt(0.8) ≈ 1.118: the camera must be about 12% farther than the threshold before it switches coarser. That is the same margin as screen size's 20%, since screen size falls with the square of distance. Only used at boundaries without a band.
  • A forced level never fades (blend stays 0). A level falling back for residency never fades either, so a fade can't show a hole while meshes stream.
  • The rule exists twice, C++ and GLSL. Drift is caught by the renderlod record (stage 7) on every readback, but any change must touch both files.
5 · Culling

Both levels pass, and a fading group's instances move to the cutout buckets

shaders/instancecull.comp · src/renderer/drawlists.*

An instance survives the LOD test if its level is the drawn one or the fading one. While its group fades it goes to the cutout bucket of its sidedness for every view, so it draws through pipelines that discard. The scatter pass computes the same bucket, so both passes agree on the region.

shaders/instancecull.compbool fadingOf(Instance inst) {
    if (inst.lodGroup == 0 || inst.lodGroup > uint(lodStates.data.length())) { return false; }
    return ((lodStates.data[inst.lodGroup - 1].y >> 16) & 0xFFu) != noLevel;
}
uint bucketOf(Instance inst, uint view, bool fading) {

    if (((inst.flags & flagCutout) != 0 && perSubmesh(inst, view)) || fading) {
        bucket += 2u;                                 // the cutout buckets
    }
    return bucket;
}

src/renderer/drawlists.cpp · the CPU side of region sizing// An instance of a render-LOD group counts in its cutout bucket as well as its own:
// while its group fades, the cull pass draws it there.
auto DrawLists::countInstance(const GpuInstance& instance, int delta) -> void {
    bool mayFade = instance.lodGroup != 0;
    auto count = [&](std::array<uint64_t, bucketCount>& buckets, uint32_t b) {
        if (b == noBucket) { return; }
        buckets[b] += delta;
        if (mayFade && b < 2) { buckets[b + 2] += delta; }
    };
    count(cameraBuckets, cameraBucketOf(instance));
    count(cascadeBuckets, cascadeBucketOf(instance));
}
Check here
  • This is the cost the review should weigh most: regions are sized on the CPU from bucket counts, and the CPU doesn't know which groups will fade, so every render-LOD instance reserves a second command. The shader guard (regionOverflow) stays at 0 on the oak.
  • For a shadow cascade, a fading instance that normally draws its whole mesh (primFirst) still draws the whole mesh, now through the cutout shadow pipeline with the dither.
  • Fading is a per-group property read from the state in both passes; it can't disagree between cull and scatter within a frame.
6 · Drawing

Coverage in the vertex stage, a complementary Bayer test in the fragment stage

shaders/lodfade.glsl · gbuffer.vert · gbuffercutout.frag · depthcutout.vert · shadowcutout.vert · cutout.frag · src/renderer/renderer.cpp · passes/*pass.cpp

The state buffer joins the geometry descriptor set as binding 4. The vertex stage turns the instance's group state into one flat float; the fragment stage compares it with a 4×4 ordered threshold at the pixel. The fading-in level keeps thresholds below the share, the drawn level keeps the rest, so each pixel is covered exactly once.

shaders/lodfade.glsl// vertex stages: an instance's coverage
float lodCoverage(uint lodGroup, uint lodLevel) {
    if (lodGroup == 0u || lodLevel == 0u || lodGroup > uint(lodStates.data.length())) { return lodCoverAll; }
    uvec4 state = lodStates.data[lodGroup - 1u];
    uint fadeLevel = (state.y >> 16) & 0xFFu;
    if (fadeLevel == lodNoLevel) { return lodCoverAll; }
    float share = uintBitsToFloat(state.z);
    return lodLevel - 1u == fadeLevel ? share : -share;   // sign picks the side
}
// fragment stages (LOD_FADE_FRAGMENT): whether the pixel belongs to the other level
bool lodFadedAway(float coverage) {
    if (coverage > 1.5) { return false; }
    const float bayer[16] = float[16](0, 8, 2, 10, 12, 4, 14, 6, 3, 11, 1, 9, 15, 7, 13, 5);
    uvec2 cell = uvec2(gl_FragCoord.xy) & 3u;
    float threshold = (bayer[cell.y * 4u + cell.x] + 0.5) / 16.0;
    return coverage >= 0.0 ? threshold >= coverage : threshold < -coverage;
}

  • The opaque gbuffer.frag path is untouched; gbuffer.vert now writes one extra flat output that only the cutout fragment shader reads.
  • The pattern is fixed in screen space: depth prepass and G-buffer discard the same pixels, so the Equal depth test still matches. 7 · Readback and check

The record that keeps the two picks honest

src/renderer/lodgroups.cpp (parseReadback) · src/renderer/renderer.cpp (cullResult) · src/view/viewcommands.cpp (renderLodRecord, expectedLevels)

A slot later, the totals and, when asked, every group's state reach CullResult. The renderlod record recomputes each group's measure on the CPU from the camera the GPU used, runs pickLodLevel twice (wanting the finest before, and the coarsest) to bound what hysteresis allows, and flags a group whose GPU level or fade share falls outside.

Check here
  • Points within 0.01% of a threshold, a band edge or a hysteresis edge are counted as onEdge, not as differences: float order differs between CPU and GPU there.
  • Per group the record carries the CPU measure and the GPU's (gpuMeasure), the fade level and share, and the expected share, which is what the USD comparison below reads.

Risks

What to weigh

cost

Command capacity doubles for render-LOD instances (stage 5)

An estimate, not measured: on the old test world about 16 MB more GPU memory for each frame in flight for the camera's draw list, and up to four times that again for the shadow cascades.

Accept until measured at scale, or count only groups near a band.

cost

Fading draws lose early depth (stages 5–6)

One fading tree adds 0.07 ms to the G-buffer pass. A forest with many trees fading at the same moment could add milliseconds.

Measure on the re-authored test world at a dense viewpoint.

look

The dither shows

No TAA; a camera parked in a band keeps the pattern; overlapping trees share pixels.

A settle time, or a per-instance pattern offset, now or after seeing it in motion.

maintenance

The pick exists twice (stage 4)

C++ and GLSL; the stage 7 check catches drift on every readback.

Acceptable while the check runs in verification.

behaviour

Distance first changes existing levels (stage 2)

Scenes authoring both now switch by distance.

Expected; the preference is a runtime setting.
